# K1.2 · Skill 管理工具组（Agent 侧）

> 环节：K1.2（依赖 K1.1） · 状态：文档（不改代码）
> 目标：让 Agent 在会话内能查、用、固化技能——新增 `skill` capability（4 工具），注册进 registry。

---

## 1. 目标与范围

- 新增 Agent 工具组 `skill`：`skill_list` / `skill_get` / `skill_run` / `skill_save`。
- `skill_run` 承载两种 kind 的执行；`skill_save` 承载 skill-creator 的落盘（固化逻辑细节在 K1.4，本环节先建工具外壳与 workflow/prompt 执行分派）。
- **不含**：Harness 收尾自动建议（K1.4）、system prompt 引导（K1.5）、CLI（K1.3）。

---

## 2. 工具定义（新建 `src/core/agent/capabilities/skill.ts`）

沿用现有 `AgentTool` 结构（name/description/parameters/readOnly/needsConfirm/execute），复用 `core/skill/store.ts`。

| 工具 | readOnly | needsConfirm | 作用 |
|---|---|---|---|
| `skill_list` | ✅ | — | 列出全部技能（name/kind/description），供 LLM 选用 |
| `skill_get` | ✅ | — | 取单个技能详情（含 steps/guide） |
| `skill_run` | ❌ | 见下 | 执行技能：workflow 型走引擎、prompt 型走一次性 Agent |
| `skill_save` | ❌ | ✅ | 固化技能落盘（避免误写技能库，需确认） |

### 2.1 skill_list / skill_get（只读）
- `skill_list`：无参 → `listSkills()` → 返回 `name·kind·description` 列表文本 + data。
- `skill_get`：`{ name }` → `loadSkill(name)`；不存在返回失败。

### 2.2 skill_run（执行分派）
参数：`{ name: string; params?: Record<string,any> }`
- `loadSkill(name)`；不存在 → 失败。
- **workflow 型**：
  - `buildStepContext(ctx.config, spec, { yes:false })` → 用 skill.steps 组装临时 WorkflowSpec（id 用 `skill-<name>-<ts>`，domain 取 ctx.domain）→ `runWorkflow(spec, stepCtx, { confirm: ctx.confirm, promptInput: ctx.promptInput })`。
  - 危险步骤经现有 confirm 桥（交互确认 / 无人值守拒绝），**语义零放松**。
  - 返回执行结果摘要（复用引擎输出）。
- **prompt 型**：
  - 复用 `AgentHarness`（或一次性 AgentBrain）：`goal = skill.guide + "\n\n参数：" + JSON(params)`，`aiRole:'agentTask'`，白名单缺省只读 + 视 guide 需要。
  - 返回 harness/brain 的 reply 摘要。
- 深度/循环：K1 的 skill_run 不允许 skill 再触发 skill_run（复用子代理 depth 思路：执行 prompt 型时子 Agent 白名单不含 skill_run；workflow 型 steps 在 K1 不含 skill.invoke——那是 K2）。

### 2.3 skill_save（固化外壳，逻辑详见 K1.4）
参数：
```ts
{
  name: string;
  title?: string;
  description?: string;
  kind: 'workflow' | 'prompt';
  steps?: WorkflowStep[];   // workflow 型
  guide?: string;           // prompt 型
  triggers?: string[];
}
```
- 组装 `Skill` → `saveSkill()`（K1.1 校验）→ 返回落盘路径。
- needsConfirm：确认信息展示 name/kind/步骤数或 guide 摘要，避免误写。

## 4. 安全一致性

- `skill_run` 不绕过任何确认：workflow 型危险步骤走 confirm 桥，prompt 型子 Agent 走 needsConfirm/无人值守拒绝。
- `skill_save` needsConfirm；名称非法由 K1.1 saveSkill 拦截。
- agent.task/子代理场景：缺省白名单（只读 + yunxiao_comment）**不含** skill_run/skill_save（写类），需显式声明才可用——避免无人值守静默执行技能。

## 6. 验收标准与冒烟点

1. 注册后 `getAllTools()` 含 skill_list/get/run/save，总数 +4；
2. `skill_list`/`skill_get` 只读、可并行（readOnly:true）；
3. `skill_run` workflow 型：造一个 shell.run echo 的 skill → 执行成功、输出含 echo 结果；
4. `skill_run` prompt 型：造 guide skill → 走 Agent（可用 stub confirm 验证不静默执行写工具）；
5. `skill_save` needsConfirm=true；缺 steps/guide 由 K1.1 校验拦截；
6. agent.task 缺省白名单不含 skill_run/skill_save（静态断言）。

---

## 7. 风险与回滚

- 风险：skill_run 的 prompt 型复用 harness 可能与主会话上下文串味 → 缓解：prompt 型用**独立** brain/harness（不共享主 history），同子代理隔离原则。
- 回滚：删除 skill.ts + registry 两行 import/注册即可。
