# K1.4 · skill-creator 固化（含 U3 自创建闭环）

> 环节：K1.4（依赖 K1.1、K1.2、K1.3） · 状态：文档（不改代码）
> 目标：把「已完成的流程/对话」自动总结固化为 skill——这是用户要的"直接总结 skills"，也承载并入的 U3「技能自创建闭环」。

---

## 1. 目标与范围

- 提供从两种来源固化技能的能力：
  1. **从工作流固化**：把已跑通/已保存的 workflow spec 转成 `kind:'workflow'` 的 skill。
  2. **从会话固化**：把当前 Agent 会话的一段成功流程，由 LLM 总结成 skill（workflow 型抽步骤序列，或 prompt 型抽操作指南）。
- **U3 闭环并入点**：Harness `runGoal` 成功收尾时给出"建议固化"信号；交互模式提示、无人值守仅记录。
- **不含**：K2 的 `skill.invoke` 组合、模板全面迁移。

---

## 2. 固化来源一：工作流 → skill

### 2.1 core 函数（`src/core/skill/creator.ts` 新建）
```ts
/** 把 workflow spec 转为 workflow 型 skill（去运行态字段，保步骤骨架） */
export function skillFromWorkflow(
  spec: WorkflowSpec,
  meta: { name: string; title?: string; description?: string; triggers?: string[] }
): Skill;
```
- 复用 `templates.ts` 已有的"骨架抽取"思路：steps 仅保留 `id/kind/title/params/dangerous/dependsOn/needsInput/when/skipIf`，剥离运行态（createdAt/domain/执行状态）。
- kind 固定 `'workflow'`；savedAt=now。

### 2.2 入口
- CLI：`sjn flow save-skill <workflowId> <skillName>`（flow 命令新增 action；读 loadSpec → skillFromWorkflow → saveSkill）。
- Agent：`skill_save` 传 `{ kind:'workflow', steps }` 直接落盘（K1.2 已有外壳）。

## 3. 固化来源二：会话 → skill（LLM 总结）

### 3.1 core 函数
```ts
/** 让 LLM 从一段执行轨迹/对话总结出 skill 草案（不落盘，返回草案供确认） */
export async function draftSkillFromHistory(
  config: SejuaniConfig,
  history: ChatMessage[],
  hint?: { name?: string; preferKind?: SkillKind }
): Promise<Skill>;
```
- 调 `chatJSON`（role:'compress' 或 'planner'，走便宜模型），system prompt 要求：阅读轨迹 → 判定该固化为 workflow 型（有明确工具步骤序列）还是 prompt 型（偏经验性操作）→ 输出 JSON：`{ name, title, description, triggers, kind, steps? , guide? }`。
- 严格校验返回（复用 K1.1 的 kind/steps/guide 约束）；不合法回喂重试最多 2 次（复用 planner 自纠错范式）。
- **返回草案不直接落盘**——交调用方确认后再 `saveSkill`（避免误固化）。

### 3.2 入口
- REPL 命令 `/skill save [name]`：对当前会话 history 调 draftSkillFromHistory → 展示草案 → inquirer 确认 → saveSkill。
- Agent 工具 `skill_save`：LLM 自己组织好 steps/guide 传入落盘（无需再总结）；或先 `skill_get`/思考后调用。

## 4. U3：Harness 完成后的固化建议（自创建闭环）

### 4.1 触发条件（harness.ts runGoal 收尾）
- `outcome === 'completed'` 且 `usage.toolCalls >= SKILL_SUGGEST_THRESHOLD`（建议 3）且本次非 skill 执行自身（防套娃）。
- emit 新事件 `HarnessEvent{ type:'skill-suggest', reason }`（外发，不阻断）。

### 4.2 两种模式的处理
| 模式 | 行为 |
|---|---|
| 交互（REPL/CLI 在场） | 提示"本次流程可固化为技能，是否保存？"→ 是则走 §3.1 draft→确认→save |
| 无人值守（agent.task/触发器，无 confirm） | **仅 logEvent 记录建议，不打断、不自动落盘**（安全：不静默写技能库） |

### 4.3 与 H4 记忆的关系
- H4 已把总结写 lesson 记忆；U3 固化建议是"把可复用**流程**沉淀为可执行 skill"，二者互补：lesson=经验教训（供 prompt 参考），skill=可执行单元（供 run/invoke）。

## 6. 安全一致性

- 一切固化落盘（saveSkill）默认需确认（REPL inquirer / agent needsConfirm）；无人值守绝不自动落盘。
- draftSkillFromHistory 只读会话历史，输出草案，不执行任何工具、不改外部状态。
- 会话历史含敏感信息时：草案由 LLM 生成 description/steps，不原样搬运密钥（沿用现有审计脱敏意识；skill 内容仍建议人工过目——故强制确认）。

---

## 7. 验收标准与冒烟点

1. `skillFromWorkflow`：给一个 spec → 产出 workflow 型 skill，运行态字段被剥离、steps 骨架保留；
2. `sjn flow save-skill <id> <name>`：已存 workflow → 生成同名 skill，`sjn skill show` 可见；
3. `draftSkillFromHistory`（可 stub LLM）：非法返回触发重试、合法返回过 K1.1 校验；
4. harness 收尾：completed 且 toolCalls≥3 → emit skill-suggest（用 onProgress 断言）；toolCalls<3 不 emit；
5. 无人值守（无 confirm）：skill-suggest 仅记录，不落盘（断言 skills 目录无新增）；
6. 固化落盘全部经确认路径（stub confirm=false 时不写盘）。

---

## 8. 风险与回滚

- 风险：LLM 总结出的 workflow 型 skill 步骤不可执行 → 缓解：草案落盘前可选"试跑"（复用 K1.3 runSkill dry-run），或仅提示用户 review；K1 先只强制人工确认。
- 风险：skill-suggest 频繁打扰 → 缓解：阈值可配 + 每会话同类只提示一次。
- 回滚：删除 creator.ts；harness 去掉 skill-suggest emit；flow/repl 去掉对应 action/命令。
