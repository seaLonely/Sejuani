# K1.3 · `sjn skill` CLI 命令族

> 环节：K1.3（依赖 K1.1） · 状态：文档（不改代码）
> 目标：提供人工管理技能的终端命令 `sjn skill list|show|run|rm`，与 agent 工具组（K1.2）平行的人类入口。

---

## 1. 目标与范围

- 新增 `sjn skill [action] [name]` 命令，动作：`list` / `show <name>` / `run <name>` / `rm <name>`。
- 复用 K1.1 存储 + K1.2 的执行分派逻辑（workflow 型走引擎、prompt 型走 Agent）。
- 交互确认走 CLI 的 inquirer（与现有 flow 命令一致）。
- **不含**：`save`（技能固化统一由 K1.4 skill-creator/agent 完成，CLI 不提供手写 save，避免让用户裸手拼 JSON）。

---

## 2. 命令设计（新建 `src/cli/commands/skill.ts`）

沿用现有命令风格（参考 `cli/commands/flow.ts`：`[action] [name]` 位置参 + loadConfig + logger）。

| 用法 | 行为 |
|---|---|
| `sjn skill` / `sjn skill list` | 列出全部技能：`name  kind  title  savedAt`，空则提示目录与如何创建 |
| `sjn skill show <name>` | 详情：title/description/triggers/kind；workflow 型列步骤、prompt 型印 guide |
| `sjn skill run <name>` | 执行技能（见 §3） |
| `sjn skill rm <name>` | 删除（removeSkill）；不存在则 warn |

选项：`-c, --config <file>`（指定配置）、`-y, --yes`（run 时跳过确认，同 flow）。

注册：`cli/commands/index.ts` 追加 `registerSkill(program)`（放在 registerFlow 附近）。

---

## 3. `skill run` 执行逻辑

复用与 K1.2 `skill_run` 相同的分派（抽为 `core/skill/run.ts` 共享，避免 CLI 与 agent 工具重复实现）：

```ts
// core/skill/run.ts（K1.3 新建，K1.2 工具也 import 它）
export async function runSkill(
  config: SejuaniConfig,
  skill: Skill,
  opts: { yes?: boolean; confirm?: ConfirmFn; promptInput?: PromptInputFn; params?: Record<string,any> }
): Promise<{ ok: boolean; summary: string }>;
```
- **workflow 型**：组装临时 WorkflowSpec（id=`skill-<name>-<ts>`，domain=config.activeDomain，steps=skill.steps）→ `buildStepContext` → `runWorkflow`（注入 confirm/promptInput/yes）。
- **prompt 型**：`new AgentHarness(config, { aiRole:'agentTask', allowTools: 只读缺省, budget })` → `runGoal(guide + 参数)`；CLI 侧注入 inquirer confirm。
- CLI `skill run` 传 `confirm: inquirerConfirm, promptInput: inquirerInput, yes: opts.yes`。

> 抽 `runSkill` 到 core 的收益：K1.2 工具、K1.3 CLI、K1.4 creator 的"试跑"都复用同一执行路径，行为一致、只维护一处。

---

## 4. 安全一致性

- `skill run` 危险步骤：workflow 型经引擎 confirm（`-y` 显式跳过时才免确认，同 flow run 语义）；prompt 型经 Agent needsConfirm。
- `skill rm` 仅删 skills 根下同名目录（K1.1 removeSkill 已限定），无穿越。
- CLI 不提供裸 `save`：技能创建走 K1.4（有结构校验与固化逻辑），降低误造脏数据风险。

## 6. 验收标准与冒烟点

1. `sjn skill list`（空）提示正确；存 skill 后再 list 显示 name/kind/title；
2. `sjn skill show <name>`：workflow 型列步骤、prompt 型印 guide；
3. `sjn skill run <workflow型>`：含 shell.run echo 的技能执行成功、输出可见；`-y` 免确认；
4. `sjn skill run <prompt型>`：进入 Agent 执行（无 key 时给出清晰未配置提示）；
5. `sjn skill rm <name>`：删除成功、再 show 提示不存在；
6. `sjn skill unknownaction`：报未知动作与可用列表；
7. runSkill 被 CLI 与 agent 工具共用（静态：skill.ts 工具 import core/skill/run）。

---

## 7. 风险与回滚

- 风险：CLI 与 agent 工具执行路径分叉导致行为不一致 → 缓解：强制共用 `core/skill/run.ts`（§3）。
- 回滚：删除 skill.ts/run.ts + index.ts 注册行；K1.2 的 skill_run 回退内联实现。
