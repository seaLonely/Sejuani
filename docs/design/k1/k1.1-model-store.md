# K1.1 · Skill 数据模型与存储

> 环节：K1.1（地基，无依赖） · 状态：文档（不改代码）
> 目标：定义 Skill 一等实体的数据结构与文件存储读写，为 K1.2/K1.3/K1.4 提供底座。

---

## 1. 目标与范围

- 定义 `Skill` 数据结构（两种 kind：workflow / prompt）。
- 实现存取模块：落盘 `~/.sejuani/skills/<name>/skill.json`，可选生成人类可读 `SKILL.md` 镜像。
- 提供 save / load / list / remove / 名称校验 等纯函数，供上层（工具组、CLI、creator）调用。
- **不含**：执行逻辑（K1.2/K1.4）、组合（K2）、CLI/工具（K1.3/K1.2）。

---

## 2. 数据结构（新建 `src/core/skill/types.ts`）

```ts
import { WorkflowStep } from '../workflow/types';

export type SkillKind = 'workflow' | 'prompt';

export interface Skill {
  /** 唯一标识，kebab-case，[a-z0-9._-] */
  name: string;
  /** 人类可读标题 */
  title: string;
  /** 适用场景描述（供 Agent 判断何时使用） */
  description: string;
  /** 触发关键词（可选，Agent 语义匹配辅助） */
  triggers?: string[];
  kind: SkillKind;
  /** kind=workflow：步骤骨架（复用现有 WorkflowStep；去运行态 id/domain 等） */
  steps?: WorkflowStep[];
  /** kind=prompt：交 LLM 执行的自然语言操作指南 */
  guide?: string;
  /** 关联信息（K2/U5 用；K1 仅存储不消费） */
  links?: { requirements?: string[]; skills?: string[] };
  /** 保存时间 ISO */
  savedAt: string;
}
```

字段约束（save 时校验/规整）：
- `name` 必填且合法（见 §4）；重复 save 同名 = 覆盖更新。
- `kind='workflow'` 必须有非空 `steps`；`kind='prompt'` 必须有非空 `guide`。校验失败抛错。
- `title` 缺省用 `name`；`description` 缺省空串。

## 3. 存储模块（新建 `src/core/skill/store.ts`）

存储根：`~/.sejuani/skills/`，每个技能一个子目录 `~/.sejuani/skills/<name>/`：
- `skill.json` —— 结构化真源（读写以此为准）。
- `SKILL.md` —— 人类可读镜像（save 时同步生成，仅供人看/团队分享，不作读取源）。

### 3.1 函数签名

```ts
/** 保存/覆盖技能：校验 → 写 skill.json → 生成 SKILL.md 镜像。返回目录路径 */
export function saveSkill(skill: Skill): string;

/** 读取技能；不存在返回 null */
export function loadSkill(name: string): Skill | null;

/** 列出全部技能（按 savedAt 倒序） */
export function listSkills(): Skill[];

/** 删除技能（整目录）；成功 true */
export function removeSkill(name: string): boolean;

/** 技能根目录（提示用） */
export function skillsDir(): string;

/** 名称合法校验（供上层复用） */
export function isValidSkillName(name: string): boolean;
```

### 3.2 SKILL.md 镜像格式（生成规则）

```md
# <title>

- name: <name>
- kind: <workflow|prompt>
- description: <description>
- triggers: <t1, t2>   （有则列）

## 步骤（workflow 型）        或   ## 操作指南（prompt 型）
1. <step.title> (<step.kind>)   或   <guide 正文>
...
```
- 生成为**只读镜像**：手动改 SKILL.md 不影响 skill.json（K1 不做反向解析；如需可作 K2+ 扩展）。

### 3.3 实现要点
- 复用 `workflow/store.ts` 与 `templates.ts` 的落盘范式（fs.mkdirSync recursive + JSON.stringify + 损坏文件 try/catch 跳过）。
- `listSkills` 遍历 skills 根下子目录，读各自 `skill.json`，损坏跳过。
- 无外部依赖（fs/os/path）。

---

## 4. 名称校验与安全

- `isValidSkillName`: `/^[a-zA-Z0-9._-]+$/`（同 templates 的 isValidName，防路径穿越）。
- save 前必过校验；非法名抛 `Error('技能名非法：...')`。
- 删除仅限 skills 根下同名目录，不接受相对路径穿越。

## 6. 验收标准与冒烟点

用 node 直调 dist 验证（隔离临时 HOME，跑完清理）：
1. **往返**：saveSkill(workflow 型) → loadSkill 取回，steps 一致；
2. **prompt 型**：saveSkill(prompt 型 guide) → loadSkill guide 一致；
3. **校验**：kind=workflow 无 steps → 抛错；kind=prompt 无 guide → 抛错；非法 name → 抛错；
4. **list 倒序**：存 2 个，listSkills 按 savedAt 倒序；
5. **覆盖**：同名再 save → 更新不重复；
6. **删除**：removeSkill → 目录消失，loadSkill 返回 null；
7. **SKILL.md 镜像**：save 后 `~/.sejuani/skills/<name>/SKILL.md` 存在且含 title/kind。
